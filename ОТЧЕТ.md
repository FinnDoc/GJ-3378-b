## 1. Цель

Освоить разработку REST API: HTTP-методы, маршрутизацию, проверку входных данных и хранение записей в базе. По варианту 9 система ведёт новости, фильтрует их по категории и ищет по ключевому слову.

## 2. Постановка и что сделано

| Требование | Как выполнено |
|---|---|
| Python и FastAPI | сервер в пакете `app` |
| Хранение в базе | SQLite, файл `news.db` |
| Модели данных | ORM-модели и Pydantic-схемы |
| CRUD основной сущности | создание, чтение, полная замена, частичное изменение, удаление |
| Фильтрация и поиск | категория и ключевое слово, без учёта регистра |
| Агрегация | число новостей по категориям |
| Валидация | ограничения длины полей |
| Сортировка, пагинация и авторизация | все три |
| Не меньше 7 эндпоинтов | 12 |
| Документация API | Swagger UI и ReDoc |

Читать новости можно без входа. Создавать может вошедший пользователь. Изменять и удалять — только автор записи.

## 5. Модель данных

**users:** `id`, `username`, `hashed_password`, `created_at`.

**news:** `id`, `title`, `content`, `category`, `author`, `owner_id`, `published_at`, `is_published`, `created_at`, `updated_at`.

Категория — строка в самой новости, отдельной таблицы нет. `owner_id` указывает на пользователя, который создал запись. Черновик отличается полем `is_published = false`.

При первом запуске создаются пользователь `admin` / `admin123` и семь учебных новостей, одна из них — черновик.

## 6. Поведение API

**Список.** `GET /news` принимает параметры `category`, `q`, `sort_by` (`published_at`, `title`, `id`), `order` (`asc`, `desc`), `page` и `page_size` (от 1 до 100). Ответ содержит `total`, `page`, `page_size` и `items`.

Поиск идёт по заголовку и тексту. Сравнение не зависит от регистра, в том числе для русских букв: запрос `спорт` находит категорию «Спорт», запрос `ФИНАЛ` находит слово «финал».

**Доступ.** Гость видит только опубликованные новости. Черновик для него отвечает `404`. После входа видны и черновики. Статистика для гостя считается только по опубликованным.

**Изменение.** `PUT` заменяет новость целиком, все поля обязательны. `PATCH` меняет только переданные поля. Чужую новость эти методы и `DELETE` не трогают и отвечают `403`. Когда черновик публикуют, `published_at` становится датой публикации.

**Валидация.** Заголовок от 3 до 200 символов, текст от 10, категория от 2 до 50. Неверное тело запроса даёт `422` и в базу не попадает.

**Вход.** `POST /auth/login` принимает форму `username` и `password` и возвращает JWT. Дальше его передают заголовком `Authorization: Bearer <токен>`. Ключ подписи можно задать переменной окружения `SECRET_KEY`.

## 7. Эндпоинты

| Метод | Адрес | Кто может |
|---|---|---|
| GET | `/news` | все |
| GET | `/news/{id}` | все, черновик — после входа |
| POST | `/news` | после входа |
| PUT | `/news/{id}` | автор, полная замена |
| PATCH | `/news/{id}` | автор, частичное изменение |
| DELETE | `/news/{id}` | автор |
| GET | `/categories` | все |
| GET | `/stats` | все |
| POST | `/auth/register` | все |
| POST | `/auth/login` | все |
| GET | `/auth/me` | после входа |
| GET | `/` | краткая справка и ссылки на документацию |

Коды ответов: `200` успех, `201` создано, `204` удалено, `401` нет входа, `403` чужая новость, `404` не найдено, `422` данные не прошли проверку.

## 8. Примеры

Фильтр и поиск одновременно:

```
GET /news?category=спорт&q=финал
```

```json
{
  "total": 1,
  "items": [
    {
      "id": 2,
      "title": "Местная команда вышла в финал чемпионата",
      "category": "Спорт",
      "author": "Игорь Спорт",
      "is_published": true
    }
  ]
}
```

Создание после входа под `admin`:

```
POST /news
Authorization: Bearer <токен>
```

```json
{
  "title": "Новость для отчёта",
  "content": "Достаточно длинный текст учебной новости.",
  "category": "Наука",
  "is_published": false
}
```

Ответ `201`, автор подставляется из логина, у записи `owner_id` этого пользователя.

Пользователь `reader` пытается изменить чужую новость `PATCH /news/2` и получает `403`:

```json
{ "detail": "Можно изменять только свои новости" }
```

Тот же запрос без токена даёт `401`. Гость, открывая черновик `GET /news/7`, получает `404`.

Слишком короткие поля при создании дают `422`: заголовок короче 3 символов, текст короче 10, категория короче 2.

`GET /stats` без входа показывает `drafts: 0`. С токеном редактора в той же базе черновики в счётчике есть.

## 9. Как проверить

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Дальше открыть http://127.0.0.1:8000/docs.

1. `GET /news` — шесть опубликованных новостей, черновика среди них нет.
2. В том же методе указать `category=спорт` и `q=финал` — одна новость.
3. `GET /news/7` без входа — `404`.
4. Кнопка **Authorize**, логин `admin`, пароль `admin123`.
5. `GET /news/7` — черновик открывается.
6. `POST /news` — новая запись.
7. Зарегистрировать второго пользователя, войти им и вызвать `PATCH` по чужому id — `403`.
8. `GET /stats` и `GET /docs` (или `/redoc`) — агрегация и документация.

Если база уже создавалась раньше, файл `news.db` лучше удалить перед запуском: таблицы и учебные записи создаются заново только для пустой базы.
